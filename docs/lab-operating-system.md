# Finance AI Lab Operating System

The repository is the shared memory of the group.

## The recurring loop

```text
Life / Work Update
        ↓
Research Question
        ↓
Reading / Source
        ↓
Discussion
        ↓
Hypothesis
        ↓
Small Experiment
        ↓
Build / Test
        ↓
Evidence
        ↓
What changed our mind?
        ↓
Next question
```

## Every meeting produces four artifacts

### 1. Meeting note
What happened, what was discussed, and what was decided.

### 2. Research note
The important source, the thesis, evidence, uncertainties, and implications.

### 3. Engineering artifact
Code, schema, prototype, test, visualization, process map, or experiment.

### 4. Next question
One clearly stated question that becomes the starting point for the next cycle.

## Two-week cadence

### Meeting 1 — Learn

- Life/work updates
- Review previous experiment
- Discuss one primary/strong source
- Teach one financial concept to the group
- Select the next engineering question

### Between meetings

- Each member spends a small amount of time on an issue or experiment
- Coding agents can accelerate implementation
- Human members review outputs and claims

### Meeting 2 — Build

- Demo what changed
- Inspect failures
- Review a PR or research note
- Update assumptions
- Select the next experiment

## Roles

Roles are temporary and should rotate.

**Financial Systems Lead**
Focuses on market structure, infrastructure, settlement, liquidity, and domain accuracy.

**AI / Engineering Lead**
Focuses on software architecture, agents, data pipelines, evaluation, and experiments.

**Research / Challenge Lead**
Focuses on sources, assumptions, unanswered questions, and stress-testing claims.

The group can also deliberately violate these roles to cross-train one another.

## Project portfolio

### Market Watcher / Market Tutor
Institutional/market intelligence and financial education.

### Money Pulse / Financial Wellness Lab
Consumer fintech, financial modeling, privacy, and human-centered financial interfaces.

### Opportunity Radar
Finding conferences, contribution pathways, communities, and learning opportunities.

### Future projects
New experiments should earn their place by answering a concrete question or testing a meaningful hypothesis.

## Project lifecycle

Every project should move through:

`Idea → Hypothesis → Prototype → Evaluation → Decision`

A decision can be:

- continue;
- revise;
- pause;
- archive;
- spin out into a standalone project.

## Contribution standard

A contribution does not have to be code.

Useful contributions include:

- a source;
- a process map;
- a financial concept explanation;
- a dataset fixture;
- a test case;
- a failed experiment;
- a better question;
- a prototype;
- a code review;
- a connection between two systems.

## The lab's most important habit

Do not ask only:

> What can we build?

Also ask:

> What can we learn by trying to build it?
