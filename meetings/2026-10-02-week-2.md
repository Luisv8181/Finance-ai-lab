# Week 2 — Build the Financial Terminal Mindset

Date: October 2, 2026

## Theme

How markets actually clear, settle, and become computable — and what an AI-native financial terminal needs underneath the interface.

## Meeting outcome

By the end of the meeting, the group should be able to explain:

1. the basic path from trade to settlement;
2. why clearing and settlement are different;
3. what data a terminal needs to represent an event correctly;
4. why timestamps and provenance matter;
5. why an AI terminal should sit on top of deterministic infrastructure;
6. what the first Open Finance Terminal MVP should and should not do.

## 90-minute agenda

### 0–10 min — Personal / work / business updates

Each person shares one meaningful update, one thing they are trying to learn, and one question or decision where the group can help.

### 10–25 min — Market mechanics primer

Discuss:

- trade date;
- clearing;
- netting;
- central counterparties;
- settlement;
- custody;
- settlement risk;
- T+1.

Core question:

> At which points does the system transform a trade into an actual financial obligation and then into settled ownership/cash movement?

Draw the process on one page.

### 25–45 min — Primary reading discussion

Primary reading:

DTCC post-trade/tokenization material from docs/reading-queue.md.

Discussion prompts:

- Which parts of post-trade are primarily movement of information?
- Which parts require legal finality or controlled ownership?
- What does faster settlement actually change?
- Which bottlenecks disappear?
- Which controls remain?
- Where could tokenization create new operational dependencies?

### 45–55 min — AI terminal case study

Read the OpenBB materials listed below.

Ask:

> What is the difference between a financial data platform, a terminal UI, and an AI agent?

Map:

Source -> tool -> evidence -> analysis -> answer

Identify where hallucination or stale data could enter the chain.

### 55–65 min — Blooper / broken assumption

Prompt:

> What financial concept sounded simpler than it actually is?

Stress-test one statement such as:

- A trade is complete when it executes.
- Faster settlement removes risk.
- A smarter model can compensate for bad data.
- A chart is evidence by itself.



### 55–68 min — Current AI in finance: from chatbot to agent

Use this as the "what is actually new?" segment.

Discuss:

- Agentic AI moving from question-answering toward bounded financial workflows.
- AI agents extracting, validating, and transmitting structured information between enterprise systems.
- AI governance becoming machine-readable infrastructure rather than only policy documents.
- Open financial data platforms exposing data to Python, APIs, terminals, and AI agents.
- The difference between an AI research assistant, a quantitative research system, and an execution-capable agent.

Current case study:

Microsoft, ANZ, HSBC, and Lloyds demonstrated a trade-finance proof of concept where agents extract and validate letter-of-credit data against ERP documents and transmit structured information to banks. The important lesson for us is the architecture: AI sits inside a structured workflow with data standards, validation, and controlled system access. https://www.microsoft.com/en-us/microsoft-cloud/blog/financial-services/2026/04/20/reimagining-trade-finance-with-ai-a-collaborative-proof-of-concept-from-microsoft-anz-hsbc-and-lloyds/

Open-source angle:

FINOS is developing governance-as-code and open specifications for agentic financial-services workflows. Ask:

> What would it mean if permissions, policies, evidence requirements, and audit events were part of an agent's technical interface?

### 68–78 min — Tool Safari

Before the build, choose one tool to actually run locally.

Start with:

1. OpenBB
2. FINOS AIGF MCP Server
3. Qlib
4. QuantConnect LEAN
5. FinRL

Full install notes and experiments: [tools/finance-ai-tool-safari.md](../tools/finance-ai-tool-safari.md).

Do not try to install everything during the meeting. The goal is to learn what each layer does, not collect dependencies.

Use the same test question where possible:

> Compare SPY and QQQ over the last 20 trading days. What changed, what evidence supports the explanation, and what would invalidate the explanation?

Score the tool by evidence path, provenance, reproducibility, failure handling, and tool boundaries rather than how polished its answer sounds.

### 78–90 min — Build lab + decisions

Move the remaining build work into the Open Finance Terminal v0 issue.

The terminal should eventually be able to compose the lessons from the tool safari:

Source data -> normalized evidence -> deterministic calculations -> bounded tools -> AI explanation -> citations -> uncertainty -> human review.

Decide which tool or architecture pattern we will borrow first.

### 65–82 min — Build lab: Open Finance Terminal v0

Create the first implementation issue around:

Terminal command router + deterministic evidence layer

Target commands:

- /quote SPY
- /macro CPI
- /filings AAPL
- /compare SPY QQQ

For v0, do not add a general-purpose agent.

Build:

- command parsing;
- one or two deterministic data adapters;
- normalized evidence objects;
- timestamps;
- source links;
- simple terminal-style output.

### 82–90 min — Decisions and commitments

Decide:

- first UI surface: CLI or web terminal;
- first data provider(s);
- evidence schema owner;
- AI-agent owner;
- next reading;
- next build issue.

Record decisions in docs/decision-log.md.
